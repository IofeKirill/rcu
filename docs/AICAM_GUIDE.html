ИИ-камера AI CAM: руководство для Е7

Это руководство относится к модулю BE-1756 AI CAM (AI Vision Module V2.0) и библиотеке aicam. В расширении раздел «ИИ-камера» доступен в наборе Е7. Старая камера с библиотекой ai остаётся отдельным устройством: её команды нельзя подставлять вместо aicam.

Источник: https://www.yuque.com/zmrobo-en/hardware/dmlxxlggllouy9fu — руководство производителя, изучено 13 октября 2026 года. Имена Python-функций и строковые режимы сверены с предоставленными пользователем примерами Робокода. Примеры ниже проверены на синтаксис и соответствие описанным вызовам; физическое тестирование этих примеров на камере ещё предстоит.

1. Подключение и первый запуск

1. Подключите шестиконтактный разъём камеры к P7 или P8 контроллера Е7. Эти порты обеспечивают последовательный обмен. Другой порт может дать питание, но не передавать данные камеры.

2. Проверьте, что TF-карта камеры установлена: на ней находится операционная система. Без карты камера не загружается.

3. Дождитесь появления интерфейса камеры. Первый запуск может занять больше времени.

4. В расширении выберите Е7 и создайте новый файл. Новый файл содержит только import rcu с комментарием. При вставке команды камеры из дерева импорт aicam добавится автоматически, если его ещё нет.

5. Для начала используйте пример «Проверка связи»: он переключает камеру и печатает результаты. Моторы в нём не используются.

6. В панели USB или Bluetooth выберите нужный контроллер. Play выполняет текст активного редактора в памяти. Для сохранения программы на контроллере используйте загрузку файла.

7. Для завершения бесконечного цикла используйте Stop. Вывод смотрите в журнале выбранного подключения.

В примерах AI_CAM = 7 — имя устройства в верхнем регистре, используемое как константа порта. Если камера подключена к P8, замените 7 на 8. Расширение сохраняет введённый регистр имени, не исправляя его автоматически.

2. Выбор режима: две разные команды

aicam.SetAICamCmd(port, mode) отправляет переключение режима. Согласно руководству, команда должна выполняться после полной загрузки камеры. Не считайте, что камера уже готова сразу после отправки.

aicam.SetWaitAICamCmd(port, mode) ждёт запуска камеры и переключения в режим, затем продолжает программу. Это блокирующая операция. Точное время ожидания и наличие внутреннего таймаута в документации не указаны. Если программа зависла здесь, сначала проверьте питание, P7/P8 и готовность камеры.

Режим — строка в кавычках, в нижнем регистре. Не передавайте числовой индекс режима из таблиц RoboEXP: в наших Python-командах используются строки.

3. Номер цели и ID — разные значения

Номер цели отвечает на вопрос «какой по порядку объект сейчас виден на экране». Цели нумеруются слева направо, начиная с 1, до 20. Если два объекта поменяются местами, номер цели может измениться.

ID отвечает на вопрос «какой это обученный объект или распознанный класс/метка». Например, лицо, обученное первым, получает ID1. Оно может быть второй целью на экране, но сохранять ID1. Смысл ID зависит от режима.

Для выбора по номеру цели:

# Первая цель слева: её ID и координата X.
target_id = aicam.GetAICam(AI_CAM, 1, 1)
x = aicam.GetAICam(AI_CAM, 1, 2)
name = aicam.GetAICamStr(AI_CAM, 1)

Для выбора по ID:

# Объект с ID1 независимо от его текущего номера на экране.
x = aicam.GetAICamIDData(AI_CAM, 1, 1)
name = aicam.GetAICamIDStr(AI_CAM, 1)

Это отдельные обращения к камере. Документация не обещает, что все последовательные чтения относятся к одному кадру. Для быстро движущихся объектов сначала измерьте устойчивость данных.

В командах по ID нет поля «ID», поэтому остальные коды сдвинуты на единицу. GetAICam(7, 1, 1) читает ID первой цели, а GetAICamIDData(7, 1, 1) — X объекта с ID1.

Начало координат — левый верхний угол, X растёт вправо, Y растёт вниз. Из описания нельзя однозначно установить, обозначают ли X/Y центр рамки или другой опорный элемент во всех режимах. Поэтому в примерах они называются координатами, без добавления половины ширины/высоты.

Размер имеет шкалу 0–100; руководство не объясняет формулу. Не подменяйте его площадью в пикселях или расстоянием до объекта. Уверенность также имеет шкалу 0–100; значения и их стабильность зависят от режима.

Строковые результаты

Строковые команды возвращают текст, смысл которого зависит от приложения: название объекта, содержимое QR-кода или название точки тела. Не приводите строку к числу без проверки её содержимого. Для первичной диагностики печатайте repr(value): так видно пустые строки и специальные символы.

Что возвращается, если цели нет

В руководстве это не определено. Пока нельзя обещать, что камера возвращает 0, -1, пустую строку или прежнее значение. Поэтому нельзя считать любое положительное значение доказательством наличия объекта без проверки.

Перед управлением моторами проведите опыт: объект в кадре → убрать объект → вернуть → закрыть объектив. Запишите результаты всех полей и строк. Проверьте, обновляются ли данные или сохраняется прошлый кадр. Это требуется отдельно для выбранного режима и прошивки.

5. Подготовка режимов на самой камере

Лица

В режиме face необученное лицо обводится белой рамкой. Совместите центральный прицел с рамкой и нажмите пользовательскую кнопку. После обучения распознанное лицо получает цветную рамку и ID. Поддерживается до 20 лиц; ID соответствуют порядку обучения.

Откройте меню внизу слева и выберите Save. Без сохранения обучение может очиститься при выходе из режима. Clear удаляет обученные данные. Для теста ниже обучите одно лицо как ID1 и сохраните.

Объекты и классификация

Режим detector использует 80 заранее предусмотренных классов COCO. Обучение здесь назначает ID распознаваемому объекту; оно не превращает произвольный предмет в новый класс нейросети. По руководству нельзя повторно обучать одну категорию.

Режим classifier предназначен для обучения собственных категорий, до пяти. Выберите ID1–ID5, удерживайте пользовательскую кнопку и покажите предмет с разных сторон до подтверждения обучения. Сохраните данные. Эти режимы решают разные задачи: выбирайте подходящий перед написанием программы.

Цвета

Камера может обучить до 20 цветов. В режиме color нажмите три точки внутри области нужного цвета, проверьте выделение, при необходимости настройте пороги LAB. Поместите прицел внутрь рамки и нажмите пользовательскую кнопку для обучения. Сохраните данные. Не обучайте одну цветовую категорию несколько раз.

Освещение влияет на результат. После изменения освещения повторно проверьте выделение. Не копируйте ID цвета из чужого проекта: он зависит от вашего порядка обучения.

Дорога

Режим road рассчитан на одну направляющую линию на однотонном фоне. Руководство явно исключает сложные карты, перекрёстки и несколько линий. Выберите три точки на линии и добейтесь устойчивого зелёного отрезка.

Камера выдаёт X верхней точки отрезка как цель 1 и X нижней точки как цель 2. Разность этих X можно использовать для оценки направления линии. Сначала смотрите её в журнале; знак будущего поворота зависит от размещения камеры и моторов.

Метки, QR-коды и жесты

Для AprilTag используйте семейство TAG36H11; диапазон меток в описании — 0–255. Генератор: https://chev.me/arucogen/ . Для первого теста возьмите простую метку с ID1.

В режиме qrcode предусмотрено чтение QR-кодов с числами, буквами и китайскими символами. Поддержку кириллицы отдельно проверьте на своей камере. Для начала закодируйте простой текст run и считайте строковую команду.

Режим gesture распознаёт шесть статических жестов обеих рук. Числовое соответствие жестов рисункам не перенесено в наше описание без проверки; выведите ID для каждого жеста и составьте свою таблицу по наблюдениям.

6. Готовые примеры в расширении

В «Примеры программ» при выбранном Е7 доступны семь файлов. Каждый открывается отдельным несохранённым Python-документом. Сохраните копию в своей папке, задайте порт и используйте Play. Полный текст каждого примера приведён ниже.

01 — Проверка связи и чтение всех полей

Файл aicam_01_probe.py. После переключения в face выводит поля первой цели и её строку. Проверьте результаты при наличии и отсутствии объекта. Это проверка обмена, а не готовый детектор присутствия.

02 — Обученное лицо с ID1

Файл aicam_02_face.py. Сначала обучите и сохраните лицо. Программа печатает ID первой цели и сообщает, когда прочитан ID1. Звуковой сигнал и движение здесь не добавлены: сначала проверяем, как меняется ID после исчезновения лица.

03 — Содержимое QR-кода

Файл aicam_03_qr.py. Выводит repr строки и сравнивает её с run. Сравнение сообщения не следует сразу связывать с запуском моторов: сначала исключите сохранение старых данных после удаления QR-кода.

04 — Координаты цвета по ID

Файл aicam_04_color.py. После обучения цвета как ID1 выводит X/Y, размер и уверенность. У GetAICamIDData X имеет код 1, Y — 2, размер — 5, уверенность — 6.

05 — Две точки линии

Файл aicam_05_road.py. Выводит X верхней и нижней точки и их разность. Для обеих целей код X равен 2. Это основа для последующей настройки регулятора; моторы в примере не включаются.

06 — Запястья человека

Файл aicam_06_human.py. Читает координаты левого запястья с ID10 и правого с ID11. Поднимайте одну руку, наблюдайте изменение X/Y, проверьте ориентацию камеры.

Во всех примерах предусмотрена пауза 0,2 секунды между чтениями, чтобы журнал оставался читаемым. Это удобная частота первичной проверки, а не заявленная максимальная частота обмена камеры.

7. Частые затруднения

Камера получает питание, но не переключается: проверьте P7/P8, кабель, полную загрузку камеры и импорт aicam. Убедитесь, что запускаете программу на том контроллере, к которому подключена камера.

Программа остановилась на SetWaitAICamCmd: команда блокирующая. Проверьте экран камеры и доступность нужного приложения. Внутренний таймаут не документирован; для завершения теста используйте Stop.

Значения кажутся сдвинутыми: проверьте, какая команда используется. Код X равен 2 для GetAICam и 1 для GetAICamIDData.

Цель меняется после перемещения: номер цели определяется положением слева направо. Для обученного объекта с постоянным ID используйте команды по ID.

Распознавание исчезло после выхода из приложения: проверьте сохранение обученных данных через Save.

Приложение закрывается сразу после запуска: производитель рекомендует проверить Runtime Library в Settings. Если она отсутствует, её установка выполняется через настройки камеры при подключении Wi-Fi.

Данные остаются после удаления объекта: зафиксируйте результаты, режим и версию прошивки. До выяснения не используйте эти данные как единственное условие движения робота.

Не виден вывод программы: откройте журнал того подключения, через которое выполнялся Play. Загрузка файла и запуск из памяти — разные действия.

8. Что проверяем на устройстве перед следующим этапом

Проверка должна подтвердить: запуск шести примеров; переключение режимов; соответствие кодов полей; строковый результат QR; отсутствие/сохранение данных при исчезновении цели; отличие номера и ID при перестановке объектов; знак координат и данных линии. После этого можно добавлять сопровождение объекта, реакцию на метку и движение по линии с остановкой при потере распознавания.

ИИ-камера: проверка связи и всех полей

# Е7: ИИ-камера BE-1756. Проверочный пример без движения моторов.
# Результат при отсутствии цели необходимо проверить на вашей прошивке.
import rcu
import aicam

AI_CAM = 7  # устройство подключено на порт Sensor 7

def task1():
    aicam.SetAICamCmd(AI_CAM, "face")
    aicam.SetWaitAICamCmd(AI_CAM, "face")
    print("id x y width height size confidence; text")
    while True:
        values = [aicam.GetAICam(AI_CAM, 1, field) for field in range(1, 8)]
        print(values, repr(aicam.GetAICamStr(AI_CAM, 1)))
        rcu.SetWaitForTime(0.2)

task1()

10. Простое движение по линии: ПД-регулятор

Файл aicam_07_line_follow.py доступен в «Примеры программ» для Е7. Это простой учебный ПД-регулятор: одно измерение нижней точки, П-составляющая, Д-составляющая и две скорости моторов. Отдельный диагностический пример aicam_05_road.py остаётся в списке.

Настройки в ячейках памяти

ЯчейкаЧто хранитсяКак используется
1Общая скоростьspeed = rcu.GetData(1)
2П-коэффициент с масштабом 10kP = rcu.GetData(2) / 10
3И-коэффициент с масштабом 1000kI = rcu.GetData(3) / 1000; в ПД не используется
4Д-коэффициентkD = rcu.GetData(4)

Значения читаются внутри функции регулятора на каждой итерации. Поэтому при изменении ячеек во время движения новый коэффициент применяется в следующем расчёте. Программа не перезаписывает ячейки стартовыми значениями.

Расчёт управления

Нижняя точка имеет номер цели 2. В GetAICam код X равен 2, поэтому читаем aicam.GetAICam(AI_CAM, 2, 2). Отклонение deviation равно (X − 320) / 6.4. Число 320 — середина кадра шириной 640, деление на 6.4 нормирует отклонение.

pReg = deviation * kP
dReg = (deviation - lastDeviation) * kD
control = pReg + dReg
lastDeviation = deviation

П-составляющая зависит от текущего смещения линии. Д-составляющая зависит от изменения смещения за одну итерацию. Управление прибавляется к общей скорости левого мотора и вычитается из скорости правого. Скорости передаются напрямую в SetMotor. На Е7 левому мотору подаётся отрицательное значение: motor.SetMotor(LEFT_MOTOR, -leftSpeed), правому — положительное rightSpeed.

В global оставлено только lastDeviation: оно изменяется в функции и должно сохраняться до следующего вызова. speed, kP, kD, pReg, dReg и control — локальные переменные одного расчёта.

Запуск

1. Настройте одну линию в режиме road на экране камеры, выбрав три точки. Проверьте показания диагностическим примером.

2. Укажите порты LEFT_MOTOR, RIGHT_MOTOR и AI_CAM. Значения рабочего примера: моторы 2 и 4, камера P8.

3. Заполните ячейки 1, 2 и 4. Ячейка 3 остаётся зарезервирована для И-составляющей других примеров.

4. Запустите Play. SetAICamCmd(AI_CAM, "road") задаёт режим, SetWaitAICamCmd(AI_CAM, "road") ожидает переключения. Затем начинается бесконечный цикл регулятора.

5. Останавливайте программу кнопкой Stop в расширении. Пример запускается прямым вызовом task1(), без if __name__ и try/finally.

Коэффициенты подбираются для своей конструкции и положения камеры. Начинайте настройку с П-составляющей, затем добавляйте Д-составляющую для уменьшения колебаний. Если робот поворачивает от линии, проверьте соответствие портов левому/правому мотору и знак управления.

В этом простом примере нет калибровки пустого кадра и автоматической обработки потери линии. Результат камеры при отсутствии линии пока не подтверждён.

# Е7: простой ПД-регулятор по ИИ-камере BE-1756, режим road.
# Сначала настройте линию по трём точкам на экране камеры.
# Ячейки: 1 — скорость, 2 — kP × 10, 4 — kD; ячейка 3 здесь не используется.
import rcu  # Основная библиотека для управления роботом.
import motor  # Библиотека для управления моторами.
import aicam  # Библиотека для работы с ИИ-камерой.

# ---------- Настройки моторов и датчиков ----------
LEFT_MOTOR = 2  # устройство подключено на порт Motor 2
RIGHT_MOTOR = 4  # устройство подключено на порт Motor 4
AI_CAM = 8  # устройство подключено на порт Sensor 8
# --------------------------------------------------

lastDeviation = 0
# Прошлое отклонение для Д-регулятора.


def LinePDCamera():
    global lastDeviation
    # В global только значение, которое сохраняется между вызовами.
    speed = rcu.GetData(1)
    # Общая скорость из ячейки 1.
    kP = rcu.GetData(2) / 10
    # Коэффициент П-регулятора из ячейки 2 с делителем 10.
    kD = rcu.GetData(4)
    # Коэффициент Д-регулятора из ячейки 4 без делителя.

    deviation = (aicam.GetAICam(AI_CAM, 2, 2) - 320) / 6.4
    # Отклонение нижней точки от середины кадра, нормированное делением на 6.4.
    pReg = deviation * kP
    # П-регулятор реагирует на текущее отклонение.
    dReg = (deviation - lastDeviation) * kD
    # Д-регулятор реагирует на изменение отклонения.
    control = pReg + dReg
    # Итоговое управляющее воздействие ПД-регулятора.
    lastDeviation = deviation
    # Сохраняем отклонение для следующего расчёта.

    leftSpeed = speed + control
    rightSpeed = speed - control
    # Подаём рассчитанные скорости на моторы.
    motor.SetMotor(LEFT_MOTOR, -leftSpeed)
    motor.SetMotor(RIGHT_MOTOR, rightSpeed)
    rcu.SetWaitForTime(0.001)
    # Небольшая пауза между расчётами.


def task1():
    aicam.SetAICamCmd(AI_CAM, "road")
    aicam.SetWaitAICamCmd(AI_CAM, "road")
    # Переключить камеру в режим линии и дождаться переключения.
    while True:
        LinePDCamera()
task1()
