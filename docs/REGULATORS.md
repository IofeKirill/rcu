# Общий стиль примеров регуляторов

Проверены и обновлены все десять исходных примеров и семь примеров новой ИИ-камеры. Общие правила ниже применяются к программам с регуляторами; примеры работы с экраном и файлами коэффициенты не используют.

## Ячейки памяти

| Ячейка | Значение | Чтение в регуляторе |
| --- | --- | --- |
| 1 | Скорость | speed = rcu.GetData(1) |
| 2 | kP × 10 | kP = rcu.GetData(2) / 10 |
| 3 | kI × 1000 | kI = rcu.GetData(3) / 1000 |
| 4 | kD | kD = rcu.GetData(4) |
| 5 | Нормировка датчика света на порту 5 | sensor.GetLightSensor(5) / rcu.GetData(5) |
| 6 | Нормировка датчика света на порту 6 | sensor.GetLightSensor(6) / rcu.GetData(6) |

Коэффициенты и скорость считываются на каждой итерации. ПД не использует ячейку 3. Примеры движения не перезаписывают настройки: заполните ячейки до запуска. Пример 8 позволяет изменить и сохранить их через экран контроллера. Нормировки света в ячейках 5/6 должны быть ненулевыми.

## Световые датчики

```python
def ReadLight(port):
    return sensor.GetLightSensor(port) / rcu.GetData(port)

deviation = ReadLight(5) - ReadLight(6)
```

Вместо сырых показаний регулятор сравнивает нормированные. Порт датчика и номер его ячейки нормировки совпадают. При переносе датчика на другой порт заполните соответствующую ячейку и учитывайте, что ячейки 1–4 заняты настройками регулятора.

## Названия и global

Отклонение называется deviation, прошлое отклонение — lastDeviation. В ПД global требуется только для lastDeviation. В ПИД дополнительно требуется global iReg, поскольку накопленное значение И-составляющей сохраняется между вызовами. speed и коэффициенты локальные.

```python
pReg = deviation * kP
iReg = max(-20, min(20, iReg + deviation * kI))
dReg = (deviation - lastDeviation) * kD
control = pReg + iReg + dReg
lastDeviation = deviation
```

У старой камеры И-составляющая ограничена от -20 до 20, у световых датчиков (примеры 1 и 8) — от -25 до 25, как в исходных программах. Это ограничение состояния, а не дополнительный коэффициент регулятора. Для ПД строки с iReg и kI отсутствуют.

## Две разные камеры

У старой камеры ai отклонение равно ai.GetAICamData(1) - 120. Переключение в режим линии оставлено как в предоставленном пользователем коде: SetAICamLED(1), SetAICamData(5, 0), SetWaitForAICamData(5, 0).

У новой камеры aicam на Е7 отклонение равно (aicam.GetAICam(AI_CAM, 2, 2) - 320) / 6.4. Сначала SetAICamCmd(AI_CAM, "road") задаёт режим, затем SetWaitAICamCmd(AI_CAM, "road") ожидает переключения. Импорты и функции этих двух камер не взаимозаменяемы.

## Что изменено в десяти исходных примерах

| Пример | Настройка и изменения |
| --- | --- |
| 1. Линия по свету | ПИД, ячейки 1–4; нормировка света 5/6; подсветка и вывод показаний сохранены |
| 2. Линия по старой камере | ПИД, ячейки 1–4; API ai и центр 120 сохранены |
| 3. Движение по энкодеру | Скорость из ячейки 1; RobotMovement(encoder), знак угла задаёт направление |
| 4. Поворот по энкодеру | Скорость из ячейки 1; RobotRotation(encoder), моторы вращаются в разные стороны |
| 5. Очистка экрана | Исходные показания датчика; очистка каждые 15 итераций; global не нужен |
| 6. Bluetooth-пульт | Скорость из ячейки 1; делитель поворота kSpeed = ячейка 2 / 10; исправлен порт энкодера клешни |
| 7. Синхронное движение | Скорость из ячейки 1; kP из ячейки 2 / 10; deviation — разность энкодеров; удалена лишняя настройка порта |
| 8. Ввод параметров | Меню speed/kP/kI/kD соответствует ячейкам 1–4; накопление iReg и lastDeviation сохраняется между вызовами |
| 9. Запись в файл | Датчик читается через sensor; десять показаний дописываются в data.txt |
| 10. Чтение файла | Строки data.txt выводятся на экран без символов перевода строки |

Для примера 6 делитель поворота не является П-коэффициентом: назначение ячейки 2 здесь другое. Чтобы сохранить исходный делитель 3, запишите в ячейку 2 значение 30. Делитель должен быть ненулевым. Удержание клешни использует её собственный энкодер на порту 2; при совпадении с целью мощность равна нулю.

В примере 8 вверх/вниз выбирают строку, вправо/влево меняют значение. Правая кнопка сохраняет настройки и запускает движение. Порядок меню: speed, kP, kI, kD. Масштаб записи обратен масштабу чтения: 1 = speed, 2 = kP × 10, 3 = kI × 1000, 4 = kD. Для света дополнительно заполните нормировки 5/6.

Примеры запускаются прямым task1(), без if __name__ и try/finally. Программное ограничение мощности удалено; И-составляющая сохраняет ограничение накопления. После конечного движения моторы останавливаются обычными командами; бесконечные программы останавливаются кнопкой Stop расширения. Примеры новой камеры 1–6 сохранены; седьмой теперь использует простой ПД. Реальные движения и распознавание камеры проверяются на роботе.

## Знак мотора в примере ИИ-камеры Е7

Только aicam_07_line_follow.py подаёт отрицательную скорость левому мотору: motor.SetMotor(LEFT_MOTOR, -leftSpeed). Для Е6 направление можно задать настройкой контроллера, поэтому общие примеры сохраняют исходный знак. Отдельных вариантов файлов и автоматического изменения знаков нет.

Пример ИИ-камеры соответствует рабочему варианту: моторы 2/4, камера 8, deviation = (X - 320) / 6.4, пауза 0.001. Комментарии портов совпадают с присвоенными номерами.
