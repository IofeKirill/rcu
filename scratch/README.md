# ZMROBO Блоки — интерфейс RoboCode, 4.5.1

Редактор переведён на Scratch Blocks из переданного `app.asar` RoboCode. Используются его формы блоков, поля, выпадающие меню, палитра, редактор чисел, выбор цвета и базовые управляющие блоки. Генератор Python остаётся нашим.

## Что изменилось

Палитра повторяет разделы присланных скриншотов; категория контроллера теперь стоит первой:

E6RCU → Мотор → Два мотора → Экран → Звуки → Датчики → Беспроводная связь → Управление → Операторы → Переменные → Мои блоки → Дополнительные датчики → Модуль линии → Расширенная беспроводная связь → Дополнительные устройства → ИИ → Сервопривод.

В аппаратной части воспроизведены 170 исходных блоков и добавлены шесть команд ИИ-камеры E7. В блочном редакторе доступны E6, M6 и E7; H убран из его списка. У M6 доступны порты датчиков P1–P5, остальные команды общие с E6. Для загрузки программы M6 используй группу E6 в основной панели расширения. Категория «Камера E7» появляется только при выборе E7. Управление, операторы, переменные, списки и подпрограммы добавляются отдельно оригинальными блоками Scratch. Разделы «Начало», «Текст и вывод» и отдельный раздел «Списки» больше не выводятся.

Для портов, моторов, направлений, цветов, режимов датчиков, частоты связи и прочих параметров используются меню внутри блоков. Цвета RGB записываются в Python как `0xRRGGBB`.

**Таймер:** раздел **E6RCU**, блоки **«Сбросить таймер»** и **«Таймер (мс)»**, сразу после кнопок контроллера. Пример: `examples/04_Timer.zmblocks`.

Меню «Файл» содержит создание, открытие, сохранение и экспорт. Кнопка Python показывает или скрывает код справа; крестик в заголовке также сворачивает панель. Перетаскивай разделители между категориями, палитрой, рабочим полем и Python, чтобы изменить ширину. При открытии проекта Python закрыт, тёмная тема включена по умолчанию. Кнопка темы переключает оформление; выбранная тема и ширины панелей сохраняются отдельно от программы. В Python подсвечиваются ключевые слова, функции, числа, строки, комментарии и скобки. Боковая панель VS Code при переходе в блоки скрывается. Запуск в модели, загрузка на робота и остановка остаются над рабочим полем.

## Работа с программой

Создай проект через системные команды расширения или открой `.zmblocks`. Стартовый блок находится в категории контроллера и выглядит как `E6RCU задача 1`.

Собирай программу из блоков. Python обновляется сразу. Основная цепочка оформляется как `def task1():` с вызовом `task1()` в конце. В Python выводятся только переменные, используемые командами; созданные, но неиспользуемые переменные остаются в палитре. Обычные отдельные цепочки команд также попадают в программу в порядке расположения на поле. Отдельный блок-значение, например таймер, используется внутри условия, присваивания или другой команды.

В «Переменных» находятся «Создать переменную» и «Создать список». После создания появляются соответствующие блоки. Имена переменных сохраняются в Python. Для имени допустимы буквы, цифры после первой буквы и подчёркивания внутри имени; пробелы и ключевые слова Python отклоняются.

В «Моих блоках» нажми «Создать блок», введи Python-имя и параметры через запятую. Для изменения используй контекстное меню определения или вызова блока. Подпрограммы генерируются как `def`, аргументы локальны. Команды подпрограммы помещаются внутрь её определения. Отметь «Возвращает значение»: внутри новой функции появится перемещаемый блок «вернуть …», а в палитре — овальный вызов для выражений. Блок «вернуть» доступен в «Моих блоках», его можно поместить в условие. Закреплённая строка из старого проекта переносится в тело функции при открытии. Обычный вызов командой тоже доступен. `global` добавляется только для присваивания глобальной переменной из подпрограммы.

Ctrl+S сохраняет проект. «Экспорт Python» сохраняет `.py`. «Открыть Python в редакторе» создаёт отдельную текстовую копию; правки копии не преобразуются обратно в блоки.

## Робот и симулятор

Выбери контроллер в блочном редакторе. Кнопка «Подключить» в верхней панели открывает выбор USB или Bluetooth, поиск устройств и отключение робота. Используется общее подключение основной панели расширения; при подключении из блоков набор команд выбирается автоматически:

- «Загрузить на робота» / F6 передаёт код текущих блоков.
- Кнопка ▶ рядом с загрузкой запускает его через USB COM или Bluetooth.
- Для USB-накопителя запускай загруженный файл из меню робота.
- ■ останавливает модель и активное подключение COM/Bluetooth. При подключении только как накопитель используй остановку на самом роботе.

Для запуска в модели настрой конструкцию, моторы и датчики. Если роботов несколько, выбери нужного в окне модели. В редакторе нажми «Симулятор». Программа передаётся напрямую; экспорт `.py` не обязателен. Кнопка только открывает модель и назначает программу выбранному роботу. Робот остаётся на месте: для выполнения нажми ▶ в окне модели.

Повторный запуск в окне модели использует последний переданный снимок. После правки блоков снова нажми «Симулятор». Выбор обычного `.py` в модели заменяет привязку снимка. Привязка действует в текущем окне; после закрытия модели или загрузки нового XML передай программу снова.

XML поля и `.zmblocks` программы сохраняются отдельно. Возможности модели остаются прежними: неподдерживаемые аппаратные команды показываются внизу панели Python и блокируют запуск в модели. Загрузка на настоящий контроллер доступна. H-RCU в модели пока отсутствует.

Для H сохранён доступ к его существующему каталогу на новом движке. Точное воспроизведение E6 сделано по присланным скриншотам; отдельного комплекта скриншотов интерфейса H не было.

## Ранее созданные проекты

Проекты первой версии открываются с переводом в новый вид. Изменение формата сохраняется по Ctrl+S. Три старых примера проверены: создаваемый Python сохранён. Простые блоки превращаются в соответствующие блоки новой палитры. Редкие выражения, для которых нет прямого соответствия, сохраняются блоками совместимости с прежним промежуточным деревом. Их можно переносить, но для изменения самой формулы нужно собрать её новыми блоками.

## Известные ограничения

Задача 1 генерируется как функция `task1()` с вызовом. Параллельное исполнение задач 2–8 пока не подключено; при выборе другой задачи редактор объясняет ограничение. Несколько роботов в модели — отдельная возможность существующего симулятора.

У двух аппаратных блоков воспроизведён внешний вид, но генерация сознательно остановлена с объяснением:

1. Количество импульсов энкодера за оборот: в предоставленных Python-командах нет однозначной функции этой настройки.
2. Координаты обученного цвета с выбором ID: документация не описывает соответствие ID и аргумента `GetAICamData`.

Для них нужен пример Python, который создаёт сам RoboCode. Остальные 174 аппаратных блока преобразуются по известным сигнатурам. Подписи и коды режимов камеры сверены со встроенной справкой; дополнительные команды QR/RFID и почвенного датчика найдены в оригинальном приложении.

Порог датчика освещённости и отдельного канала линии хранится генератором в программе и применяется в соответствующем цифровом блоке. Это сравнение по текущим показаниям, а не изменение прошивки датчика. Значения соответствуют шкале выбранного устройства: у модели освещённость 0–100. Автономное движение по линии и групповое распознавание используют штатные настройки библиотеки.

Проверены загрузка интерфейса и всех категорий в DOM-среде, создание всех аппаратных блоков, таймер, списки, редактирование подпрограмм, миграция примеров и передача Python в настоящий исполнитель модели. Полная визуальная проверка в окне VS Code и аппаратная проверка на роботе здесь не выполнялись.

## Примеры

- `01_Forward.zmblocks` — моторы 1 и 3, одна секунда движения.
- `02_Line.zmblocks` — простая линия, световой датчик P5, моторы 1 и 3.
- `03_Variables.zmblocks` — изменение скорости через переменную.
- `04_Timer.zmblocks` — сброс таймера, движение до 1000 мс, остановка.

Рядом лежат соответствующие `.py`. `examples/v1/` содержит исходные примеры первой версии для проверки совместимости. В браузере можно открыть `media/preview.html`: редактор, сохранение и экспорт работают отдельно; соединение с контроллером и моделью доступны внутри VS Code.

В операторах «abs от …» вычисляет модуль, «sgn от …» возвращает −1, 0 или 1. В Python для `sgn` автоматически добавляется функция.

## Подпрограммы, порты и навигация

Порты P1–P8 в аппаратных блоках теперь являются входами. По умолчанию внутри стоит компактный выбор порта; вместо него можно перетащить переменную, аргумент подпрограммы или выражение с числовым результатом. В Python порт передаётся как число (`5`, а не строка `"P5"`). Для M6 меню ограничено P1–P5; для камеры E7 — P7/P8. Константы проверяются при генерации, вычисляемые значения — библиотекой при выполнении.

В математическом меню `sgn` стоит сразу после `abs`. Палитра при наведении расширяется до ширины команд, перекрывая рабочее поле, а после ухода мыши возвращается к заданной ширине. Проект при этом не перезагружается.

Кнопка с изображением карты рядом с масштабом открывает обзор всего проекта. Нажатие или перетаскивание по мини-карте переносит рабочую область; оранжевая рамка показывает видимую часть. Escape закрывает обзор.

Пример `examples/05_Return_Port.zmblocks` показывает подпрограмму `ReadLight(port)` с возвратом показания датчика внутри функции и вызовом для порта 5.

## Правки 4.5.1

В датчиках есть сравнение освещённости с числом (`<`, `>`, `=`). Порты моторов M1–M4 принимают переменные, параметры и выражения, как порты датчиков. Четыре арифметические операции объединены в один блок с меню `+`, `−`, `×`, `:`; старые арифметические блоки продолжают открываться.

Поля аргументов в вызовах подпрограмм позволяют вводить значения с клавиатуры или вставлять блоки. Ctrl+Z и Ctrl+Shift+Z выполняют отмену и повтор блоков один раз; при вводе текста действует обычная отмена редактирования поля.

Список USB открывается сразу и пополняется по мере поиска: найденные накопители видны до завершения сопоставления COM-портов. Подключение к выбранному устройству начинается после завершения сопоставления, чтобы сохранить связь с правильным контроллером. Время обнаружения зависит от Windows и оборудования.
